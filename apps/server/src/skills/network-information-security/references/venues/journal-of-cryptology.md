# Journal of Cryptology

## Hard constraints

- Submit original work that is not under consideration elsewhere and has been approved by all authors and the responsible institutions.
- Follow the live Springer Nature Journal of Cryptology submission guidelines and Editorial Manager requirements for manuscript source, title page, author information, declarations, permissions, and supplementary material.
- Use the current Springer Nature LaTeX workflow/template requested by the journal; do not alter margins, font size, or layout to create artificial space.
- The public journal-wide submission guidelines do not state a single hard page limit. Plan for a self-contained cryptology article and re-check the live instructions and selected article type before submission.
- Complete required ethics, competing-interest, funding, data/code availability, copyright, and third-party-permission declarations in the current Springer workflow.

## Writing and review priorities

- State the formal model, security definitions, adversary capabilities, assumptions, and parameter choices unambiguously before claiming security.
- Give complete, auditable constructions, reductions, proofs, attacks, or complexity analysis; isolate all unproven assumptions and quantify concrete security where relevant.
- Explain the novelty in relation to the closest cryptographic literature and distinguish a new result from a repackaging of a known technique.
- Treat efficiency claims as evidence: give asymptotics plus concrete costs, comparison conditions, and implementation or parameter details where applicable.
- Make the archival argument self-contained; supplementary files may aid reproducibility but must not hide essential definitions or proof steps.

## Planning checklist

- [ ] Confirm fit with Journal of Cryptology and the selected article category in the live Springer submission system.
- [ ] List every security notion, assumption, adversary capability, and parameter regime before drafting the main theorem statements.
- [ ] Trace each claimed property to a complete proof, reduction, attack analysis, or explicitly labelled conjecture.
- [ ] Compare exact assumptions, models, and concrete efficiency with the nearest prior work.
- [ ] Validate the current template, declarations, source archive, permissions, and any artifact-availability statement before submission.
