# Security Top-4

Use one shared writing profile for IEEE S&P, USENIX Security, ACM CCS, and NDSS. Optimize for a skeptical systems-and-security reader; do not introduce conference-specific style distinctions.

Establish the security problem, protected assets, adversary, trust boundaries, assumptions, and practical impact before mechanism details. Keep the chain from threat model through design, analysis, evaluation, and limitations auditable. Tie every contribution to manuscript evidence, distinguish security guarantees from empirical observations, and make baselines, workloads, experimental methodology, deployment constraints, operational tradeoffs, and reproducibility details explicit.

State the technical contribution and its novelty boundaries against prior work precisely, with formal or empirical justification as appropriate. Discuss deployability, ecosystem assumptions, interoperability constraints, limitations, ethics, and ethical handling of data and disclosure candidly. Prefer direct technical prose and calibrated claims over inflated novelty language. Never invent experiments, citations, guarantees, or deployment evidence.
